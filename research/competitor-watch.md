# 競合ウォッチ運用

類似アプリの動向・ユーザー不満を定点観測し、ロードマップの根拠に使う。
初回調査（2026-10-16）の結論と戦略は Issue #16〜#28 のマイルストーン（v1.1〜v1.3）に反映済み。

## 運用サイクル（月1回）

1. `bash scripts/competitor-watch.sh` を実行 → `research/snapshots/YYYY-MM-DD.md` が生成される
2. 前回スナップショットと比較して確認する観点:
   - 競合の新機能（リリースノート）— 特にヒビカサネ類似の「出口」機能（動画/比較画像の書き出し）
   - 低評価レビューの新しい不満テーマ → ヒビカメの改善 Issue 候補
   - 評価数の伸び（勢いのある競合の検知）
   - ヒビカメ自身の評価・レビュー（返信すべき不満がないか）
3. 気づきがあれば Issue 化（label: feedback）し、スナップショットを commit

Claude Code に「競合ウォッチして」と頼めば 1〜3 を代行する（スクリプト実行→前回比較→所見レポート→Issue 提案）。

## X（Grok）での用途発見（補助・月1回）

レビュー欄は「既存アプリへの不満」しか拾えないため、新しいユースケースの発見は X を使う。
Grok に投げるテンプレクエリ:

```
直近1ヶ月の日本語ポストから、以下に関する不満・要望・工夫を要約して:
1. 「定点観測 写真」「同じ場所 毎日 撮影」
2. 「成長記録 写真 アプリ」「子供 成長 比較 写真」
3. 「ビフォーアフター 写真 撮り方」「筋トレ 記録 写真」
それぞれ、どんな用途・文脈で困っているか、使われているアプリ名、未充足のニーズを挙げて。
```

得られた未充足ニーズは Issue 化（label: feedback）して溜める。
トレンド追従で機能を増やすより、習慣化ループ（v1.1）→信頼（v1.2）→作品化（v1.3）の完成が優先。

## 初回調査の要点（2026-10-16 時点）

- ゴースト撮影（透かして撮る）はコモディティ。直近リリースの類似アプリが約10本あり、ほぼ全て評価1〜5件で勝者不在
- 勝ち組は「共有できる成果物（動画・比較画像）」か「毎日開く理由」で勝っている。撮影体験では勝負がついていない
- レビュー欄の主要な不満 = ヒビカメの機会:
  - データ喪失・囲い込み（Photo Diary）→ #23 書き出し
  - 過去写真を取り込めない（複数アプリ）→ #22 取り込み
  - 広告がシャッターを覆う（タイムスタンプカメラ）→ 広告ゼロ訴求 #21
  - 撮影前後で倍率が変わる・ダークモードで文字が消える → #24 品質チェックリスト
- 詳細データ: `research/snapshots/2026-10-16.md`
